# Аудит финансовых моделей с GigaChat

Локальный учебный сервис: загрузка XLSX, фоновый анализ через GigaChat Ultra, четыре раздела заключения, просмотр исходных ячеек и скачивание HTML/JSON/PowerPoint. Backend — FastAPI, интерфейс — React, агентная обвязка — собственная. В Docker используются PostgreSQL и S3-совместимое хранилище SeaweedFS.

## Быстрый запуск

Нужны Docker с Compose и `python3`. Если `.env` ещё нет, создайте его по `.env.example` и задайте `GIGACHAT_CREDENTIALS`. Уже настроенный `.env` не перезаписывайте. Ключ не входит в образ и передаётся контейнерам как файл Docker secret.

```bash
./scripts/start.sh
```

Откройте **http://127.0.0.1:8000**. Выберите `.xlsx` до 20 МБ и режим анализа. В режиме GigaChat выбранные агентом фрагменты книги передаются в API провайдера. Режим «Локальная проверка» не обращается к LLM: он проверяет структуру и поддерживаемые финансовые связи, показывает кандидатов с источниками и ограничениями.

Скрипт учитывает кириллицу и пробелы в пути проекта. При первом запуске скачиваются зависимости и образы. Для уже собранного образа: `./scripts/start.sh --no-build`.

```bash
docker compose ps
docker compose logs --tail=50 api worker
docker compose down  # останавливает сервис, сохраняя тома с данными
```

После изменений кода запускайте `./scripts/start.sh` для пересборки. Не добавляйте `--volumes` к остановке, если нужны сохранённые задачи и файлы.

## Что делает агент

1. **Аудит расчётов:** изучает формулы, сохранённые ошибки и зависимости; проверяет выбранные методологические гипотезы адресным чтением и дополнительными расчётами.
2. **Предпосылки:** определяет важные inputs, анализирует их роль и внутреннюю согласованность; может рассчитать локальную чувствительность заданного выражения.
3. **Качество модели:** формирует заключение с учётом подтверждённых наблюдений и ограничений. Число технических ошибок не считается финансовой оценкой.
4. **Бизнес:** собирает краткий обзор показателей и динамики по доступным источникам внутри книги.

Каждый блок выполняется отдельно и сохраняется в checkpoint. Агент вызывает только разрешённые инструменты. Ссылки в заключении проверяются: ячейка должна существовать и быть фактически прочитана. В интерфейсе ссылка открывает исходное сохранённое значение, формулу и соседние подписи. Исходный XLSX не пересохраняется; SHA-256 контролируется при загрузке и выполнении.

Перед аудитом, предпосылками и бизнес-обзором строится ограниченная стартовая карта финансовых строк. Она передаёт реальные значения и формулы, подписи и заголовки, сохраняет принадлежность листу и отделяет основные выходы от сеток What-if Data Table. Это эвристика навигации, а не полный перечень показателей или автоматическое определение периметра компании.
## Разработка без Docker

Python 3.11+, Node.js 24 и npm. Создайте отдельное окружение и соберите интерфейс:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
npm --prefix frontend ci
npm --prefix frontend run build
npm --prefix pptx_runtime ci --ignore-scripts
```

`requirements.lock` уже включает проверенный Spreadsheet Auditor. При минимальной установке через `pip install -e .` его можно добавить extra-командой `.venv/bin/python -m pip install -e '.[supplemental]'`. Без него основной анализ работает, а дополнительная проверка явно помечается `unavailable`.

В двух терминалах из корня проекта:

```bash
PYTHONPATH=src .venv/bin/python -m uvicorn finmodel_audit.server:app --host 127.0.0.1 --port 8000
PYTHONPATH=src .venv/bin/python -m finmodel_audit.worker
```
